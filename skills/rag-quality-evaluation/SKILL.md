# RAG 问答质量评测

固定资料与题集，从证据命中、答案忠实度到引用与拒答逐层定位问题，形成可追溯的 Bad Case 与复测记录。

## 输入与开始条件

- 资料快照及文档、章节标识
- 问题集、参考要点和应引用的依据
- 待评估系统的回答、引用及可用的检索记录
- 评测口径、版本及允许调用的运行环境

先核对现有材料与本次交付目标。缺少会改变业务判断的依据时保留待确认项，其余可独立推进的部分继续完成。

## 执行流程

1. 冻结资料、问题、参考要点与版本，建立独立评测目录。
2. 按直接规则、多文档关联、资料冲突、过期版本和资料不足设计题型。
3. 保留系统原始回答与引用，检索过程和答案判断分别记录。
4. 先核对引用是否存在及引文是否对应原文，再按参考要点评估语义与边界。
5. 按检索遗漏、证据误用、回答歧义、失效版本、拒答错误分类 Bad Case。
6. 修改后使用同一题集与口径复测，记录变更因素和剩余问题。

## 关键判断

- 区分检索命中、回答忠实度与业务正确性，分别计分。
- 资料没有给出优先级时保留冲突，缺少依据时标记资料不足。
- 引用绑定文档版本、章节与原文片段，更新资料后检查旧片段是否仍被使用。
- 结构校验通过后继续进行人工语义审查，报告明确标注检查方式。

## 交付与验收

- 含原始问题、回答、依据、评分与错误分类的评测记录
- 可复现的资料与题集版本清单
- Bad Case 改进建议与同口径复测对照

- 每个结论可以回到原始回答与具体资料片段。
- 拒答、冲突及引用问题有独立记录。
- 自动结构检查与人工语义评分分栏保留。

## 参考与示例

- 需要字段、评分或版本细则时读取 [执行约定](references/guide.md)。
- 使用 [独立构造示例](assets/example.json) 理解输入结构，按当前任务提供的资料与配置执行。
- 运行 `python3 scripts/check_evidence.py assets/example.json` 检查样例的引用结构与证据对应。
