# 企业业务流程产品化

从业务目标与现有操作出发，建立对象、状态、责任人与完成条件，明确方案取舍、异常路径和可验收范围。

## 输入与开始条件

- 业务目标、现有表单和用户操作证据
- 角色职责、权限边界及交接关系
- 现行规则、例外情况与可用资源
- 计划交付范围、系统约束和验收参与人

先核对现有材料与本次交付目标。缺少会改变业务判断的依据时保留待确认项，其余可独立推进的部分继续完成。

## 执行流程

1. 梳理当前操作路径，标注重复录入、信息断点、等待与核对环节。
2. 识别核心业务对象、唯一标识及对象之间的关联。
3. 定义状态、触发动作、执行角色、前置条件和完成条件。
4. 按角色画出主线、交接、分支、退回和异常恢复路径。
5. 记录保留、调整和暂缓的需求及理由，收敛最小交付范围。
6. 形成字段、交互、权限、接口依赖和验收场景，并建立需求到交付的对应关系。

## 关键判断

- 完成条件同时描述业务结果与责任确认，审批状态、接收状态和归档状态分别定义。
- 需求来源标注用户反馈、业务记录、数据观察或管理要求，判断与事实分栏记录。
- 前置条件失效时明确进度、输入与已完成步骤如何保留及恢复。
- 重试、并发、历史数据与撤回规则在关键操作处给出可验证处理方式。

## 交付与验收

- 业务对象与字段说明、角色责任表
- 状态机、泳道流程与异常恢复说明
- 方案取舍记录、交付范围与验收场景

- 每条关键流程有开始条件、责任角色和完成证据。
- 关键状态都有可达路径，退回与恢复可追踪。
- 需求、页面或接口与验收场景可互相定位。
