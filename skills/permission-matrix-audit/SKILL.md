# 多角色权限矩阵与回归验收

围绕角色、资源与动作核对授权规则，覆盖权限继承、单独授权、降级移除和旧入口，输出可追踪的回归矩阵。

## 输入与开始条件

- 角色、资源范围和允许操作
- 授权继承、覆盖、独立管理权限的明确规则
- 关键页面、下载、接口和消息入口清单
- 隔离测试账号、构造资源与允许执行的测试范围

先核对现有材料与本次交付目标。缺少会改变业务判断的依据时保留待确认项，其余可独立推进的部分继续完成。

## 执行流程

1. 建立主体、资源、动作三维清单，确认规则来源和优先级。
2. 将有效授权与明确拒绝条件整理为权限矩阵。
3. 按角色设计预览、下载、编辑、成员管理及审批等正向和负向场景。
4. 测试授权变更、角色降级、成员移除和单独授权叠加的结果。
5. 检查旧链接、缓存页面、消息卡片和直接请求的访问结果。
6. 保存预期、实际、证据及缺陷，修复后按受影响角色回归。

## 关键判断

- 角色名称、页面可见性与实际操作授权分别核对。
- 先确认权限继承和例外规则，再推导有效权限。
- 授权变更应在资源访问与实际动作处重新校验。
- 隔离账号与资源使用明确标识，测试记录去除凭据及真实身份。

## 交付与验收

- 角色、资源、动作与有效权限矩阵
- 正向、越权、撤权和历史入口测试用例
- 包含实际证据和修复回归结果的权限检查记录

- 矩阵中的关键允许与拒绝规则均有测试覆盖。
- 下载、编辑和审批等动作有独立校验记录。
- 权限变化后的旧入口和独立权限结果符合规则优先级。
