# 多约束菜单编排

区分硬约束与偏好，在预算、忌口和菜式结构下编排菜单，解释冲突与替换理由，保留需要人工确认的信息。

## 输入与开始条件

- 候选菜品、价格单位、人数口径及可用状态
- 用户明确提供的忌口、食材限制和偏好
- 菜式结构、数量、预算及其他业务规则
- 历史使用记录与允许采用的重复控制规则

先核对现有材料与本次交付目标。缺少会改变业务判断的依据时保留待确认项，其余可独立推进的部分继续完成。

## 执行流程

1. 统一菜品标识、食材标签、价格单位和份量口径。
2. 将明确禁用项和数量要求定义为硬约束，将口味和历史偏好定义为软约束。
3. 先筛除不满足硬约束的候选，再按菜式结构与偏好形成草案。
4. 逐项核对忌口、数量、总额、重复食材与数据完整性。
5. 替换菜品后重算受影响约束，保留原选择与替换理由。
6. 输出菜单、费用构成、冲突清单和人工确认项。

## 关键判断

- 食材与限制标签以提供的资料为准，缺失信息进入待确认清单。
- 价格按每份、每位等单位计算，并注明人数和数量口径。
- 候选不足或规则冲突时说明不能同时满足的条件及可选调整。
- 检索、规则校验与模型建议分别记录，保留最终确认人和确认版本。

## 交付与验收

- 带菜品标识、数量和价格口径的菜单草案
- 约束检查、费用计算与冲突说明
- 菜品替换记录及人工待确认项

- 硬约束逐项通过或给出明确冲突。
- 总额可按菜品、单价、单位和数量复算。
- 替换操作后重新核对全部受影响条件。
